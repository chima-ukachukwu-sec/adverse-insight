# Security Policy

## Reporting a vulnerability

Email **chima.ukachukwu.sec@gmail.com** with `SECURITY` in the subject line.

Please include what you found, how to reproduce it, and what an attacker
could do with it. I will acknowledge within 72 hours and tell you whether I
plan to fix it, and by when.

Do not open a public issue for anything exploitable. If you would prefer to
encrypt, say so in a first message and I will arrange a channel.

## Scope

This is a portfolio project, not production software. It has no users to
protect and holds no data. What is in scope is anything that would mislead
someone reading the output, or that would harm a person running it locally:

- Command or code injection through file upload or user input
- Path traversal in file handling
- Dependency vulnerabilities with a practical exploit path
- Output that could be manipulated by content inside an analysed document

## What this project is not

It does not defend against prompt injection. Where an LLM processes untrusted
input, treat the output as untrusted too. Failure modes I have already tested
and documented are described in the README rather than hidden.

## Out of scope

- Findings that require a compromised local machine
- Denial of service against a locally run instance
- Reports generated by automated scanners with no demonstrated impact
